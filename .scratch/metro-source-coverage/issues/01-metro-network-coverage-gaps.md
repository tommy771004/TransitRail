# 01 — 補上零覆蓋的地鐵網路

**What to build:** 使用者選了一個國家，卻發現該國最大的地鐵系統根本不在選單裡。中國有 54 個城市有地鐵，repo 一個地鐵站都沒有；日本 12 個城市，repo 只有東京 5 條線；韓國 8 個城市，只有首爾。

完成後：每個宣稱支援的國家，其主要地鐵網路都能查——不是拓撲上存在，而是**真的查得到班次**。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

## 為什麼不能只補拓撲

曼谷與東京的拓撲已在 2026-08-02 補完（曼谷 7 線／176 站／17 換乘站；東京 5 線／123 站／13 換乘站），但兩者在嚴格門檻下**仍然隱藏**，使用者看不到——因為它們沒有可驗證的時刻表。稽核腳本佐證：泰國 167 站全部標「無班表」。

先補拓撲再等資料是可行的順序，但只補拓撲不會讓任何一個網路變成可用。**每個網路都要先有時刻表來源，拓撲才有意義。**

- [ ] 為每個目標網路先確認可取得的官方時刻表來源，並記錄於 `METRO_DATA_SOURCE_AUDIT.md`
- [ ] 沒有可驗證來源的網路不加入 repo——寧可缺席，也不要再多一份看不到的合成資料
- [ ] 有來源的網路：接上 adapter、產出通過真實性判定為 `scraped` 或 `realtime` 的資料
- [ ] 補上該網路的線路拓撲，換乘站經 `stationAliases` 解析（跨系統異名）
- [ ] `npx tsx scripts/audit-station-mapping.ts` 0 個名稱不一致
- [ ] 該網路的選單站點，每一個都至少有一個可達目的地
- [ ] `npm run lint` 綠燈

**已完成 1/8：Toei 三田線。** `api-public.odpt.org` 對 Toei 免 key，實測回傳真實官方時刻表——平日 202 班、週六 175 班，涵蓋 00:08–23:54。已加入 `odptRoutes.ts`（Jimbocho ↔ Otemachi，兩站都已在既有選單裡）與 `stations.ts` 拓撲（27 站，站序取自 ODPT feed 本身而非維基，與時刻表 adapter 讀同一個來源）。

## 進度：大阪 Metro（2026-08-02）— 阻塞，無可用官方來源

五個管道全部查過，都不通：

| 來源 | 結果 |
| --- | --- |
| ODPT 公開端點 `api-public.odpt.org/api/v4/odpt:Operator` | 只回 **1 個 operator（Toei）**，無大阪 |
| ODPT CKAN 資料目錄 | 查 "Osaka" 只有阪急渡輪（渡輪，非鐵道） |
| 大阪市 open data portal `data.city.osaka.lg.jp` | 連線 timeout（可能地域限制或服務中斷） |
| GTFS-JP 公開清單 | 以公車為主，無確認的大阪鐵道項目 |
| Osaka Metro 官網 | 有時刻表查詢 UI（`kensaku.osakametro.co.jp/timetable/ja/`），**無 API／JSON 端點** |

**授權是硬阻塞。** `osakametro.co.jp/site_info.php` 的著作權條款：

> 著作権法上認められた場合を除き、当サイトの掲載コンテンツを複製・転用する際は、必ず事前に当社にご相談ください。

明示需事先徵詢同意，與 ODPT Toei 的 **CC BY 4.0**（明示開放）性質完全不同。刮取官網會同時踩到脆弱來源與授權兩條線——後者不是技術問題，不能靠工程手段繞過。

**結論：在取得授權或大阪 Metro 公開機讀資料之前，不實作。** 依本專案原則，寧可缺席也不加入無可驗證來源的網路。

- [ ] （若要推進）向 Osaka Metro 詢問資料使用授權，或確認大阪市 open data portal 是否含地鐵時刻
- [ ] 在授權明確之前不得刮取官網時刻表頁

### 仁川：三份資料實測全部到手

1. **時刻表** — 每條線 × 平日/假日 × 上/下行各一個資料集
   - 1 號線：`15051203`（平日上）、`15051204`（平日下）、`15051205`（假日上）、`15051206`（假日下）
   - 2 號線：`15051210`（平日上）起
   - 實測下載成功：131 個車次，cp949 編碼，寬表格式（每列一車次 × 全部停站時刻）
   - 資料形狀與首爾 artifact 相同（車次 × 停站 × 時刻），**可複用 `SeoulSubwayArtifact` 管線**

2. **車站字典** — `15083751 인천교통공사_도시철도역사정보`
   - 68 站，含 `영문역사명`（英文站名）、線路、轉乘、經緯度
   - 1 號線 33 站、2 號線 27 站、7 號線 11 站

3. **對應驗證** — 時刻表表頭的 33 個韓文站名，車站字典**100% 涵蓋**（0 個缺漏）
   - 範例：검단호수공원 → Geomdan Lake Park、계양 → Gyeyang

### 為什麼需要新的站名字典

`seoulStationNameFromKorean()` 已有韓文→英文的解析機制，但實測對仁川 **0/25 涵蓋**——`seoulSubwayStations.json` 只含首爾網路。仁川需要自己的字典，來源就是上面的 `15083751`。

這個機制存在的理由（見 `seoulStationNames.ts` 檔頭）同樣適用：搜尋以英文選單名比對，adapter 若直接吐韓文站名，會讓選單多出查不到的站。

**產出：** `src/data/scraped/korea/incheon-subway-timetable.json.gz` — 52 站、1,414 車次（1 號線 574／2 號線 840），平日 780／假日 634。

**兩個實作中發現的陷阱，都已修並加測試：**

1. **同機關兩條線用不同欄名** — 1 號線是 `열차번호`，2 號線是 `순번`。解析器原本只認前者，2 號線靜默產生 0 筆；是 `dropped` 計數（`no 열차번호 column: 232`）讓它現形，而不是「574 筆看起來有資料」。現在兩種都接受。
2. **真實性判定器不認得新來源** — `OFFICIAL_SOURCE_LABELS` 少了仁川標籤，於是 artifact 答得出 136 筆但判為 `unknown` → 不可搜尋。這是 fail-closed 設計正確運作（新 feed 沒有自動取得官方身分），補上標籤即解。
