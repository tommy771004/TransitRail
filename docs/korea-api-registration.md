# 韓國時刻表資料來源：申請與接入流程

更新日期：2026-08-01

## 為什麼需要這份文件

韓國是全專案覆蓋率最差的國家：

| | 車站選單 | 可查到時刻表 | 覆蓋率 |
| --- | --- | --- | --- |
| 韓國 | 305 | 9 | **3.0%** |
| 泰國 | 119 | 5 | 4.2% |
| 新加坡 | 145 | 7 | 4.8% |
| 香港 | 98 | 8 | 8.2% |
| 日本 | 49 | 14 | 28.6% |

原因不是爬取失敗，是**韓國從來沒有在爬**。`scripts/scrapers/korea.ts` 是 `SnapshotScraper`：

> Korail (korail.com global + the legacy letskorail.com) actively blocks automated
> browsers as "macro activity" (CODE : -8003), so a live scrape never succeeds in
> the daily GitHub Actions job — every route fell back to synthetic data.

那 9 條路線寫死在 `scripts/scrapers/routes.ts` 的 `koreaRoutes`，每天的排程只是把同一份策展 JSON 重蓋日期。排程再健康也不會增加任何覆蓋。

要真正修好，唯一不涉及捏造時刻表的路徑是接官方開放資料。

## 兩個來源，各自解決不同的洞

| --- | --- | --- |
| 主管 | 국토교통부（公共資料入口 data.go.kr） | 首爾市 |

| 能救的站 | 청량리(清涼里)、수원、동대구、광명… | 시청(市廳)、충정로(忠正路)、을지로입구… |
| 金鑰核發 | 개발계정多為自動核准 | 註冊後即時發給 |
| 主要障礙 | 註冊需本人認證（待實測） | **註冊需韓國身分，外國人無法完成**（已實測） |

- `청량리 → 서울역`：청량리是 Korail 城際站 → 需要 **TAGO**
- `시청 → 충정로`：兩站都是首爾地鐵 → 需要 **서울 열린데이터광장**

註冊流程第 2 步「身份驗證」即使選擇「外國成員（외국인 회원）」，四種驗證方式仍全部需要韓國本地身分基礎設施：

| 驗證方式 | 實際需要 |
| --- | --- |
| i-PIN | 외국인등록번호（須在韓居留並辦理外國人登錄） |

| 聯合證書（공동인증서） | 韓國金融機構（금융결제원／KOSCOM／한국정보인증／한국전자인증／KTNET）帳戶 |
| 私人認證 | Toss、Kakao Bank、國民、友利、新韓、Hana —— 全部需韓國銀行帳戶 |

台灣申請者若無韓國居留或韓國銀行帳戶，**這條路是死的**，不要在此耗時間。

### 關鍵區別：「不用註冊」分兩種

data.go.kr 的「開放資料」不代表整站都免註冊。實際上分三層：

| 動作 | 需要註冊？ |
| --- | --- |
| 瀏覽目錄、看資料集說明頁 | ❌ 不需要 |
| **下載 파일데이터（CSV／XLSX／JSON）** | ❌ **不需要** ← 我們可以用這個 |
| 呼叫 오픈API（需 `serviceKey`） | ✅ **需要**帳號 |

也就是說：你說的「不需要註冊」對**瀏覽和檔案下載**成立，但對 **API 呼叫**不成立。
而本專案要的是靜態時刻表 —— **檔案下載完全夠用**，所以註冊卡關並不擋路。

## A. data.go.kr（TAGO 열차정보서비스）

官方入口：<https://www.data.go.kr/>

### A1. 會員註冊

1. 右上 `회원가입` → 選 `개인회원`（個人）。
2. 完成本人認證。

> ⚠️ **這是外國申請者最可能卡住的一步。** 韓國的本人認證通常需要韓國手機門號或 I-PIN。
> 入口有提供外國人／無韓國門號的替代路徑（例如以護照或 Email 驗證的方式），但實際選項會隨政策調整。
> **請在這一步先確認能否通過再往下走** — 若無法通過，B 方案（首爾）不需要這道認證，可以先做 B。

3. 驗證 Email 後登入。

### A2. 找到並申請 API

1. 直接開啟 <https://www.data.go.kr/data/15098552/openapi.do>（국토교통부_(TAGO)_열차정보）。
2. 進入該 API 頁面 → 點 `활용신청`（申請使用）。
3. 填寫：
   - `활용목적`：選 `웹 사이트 개발` 或 `앱 개발`
   - 用途說明：寫清楚是跨國轉乘時刻查詢服務（審核會看）
4. 勾選同意條款後送出。
5. **개발계정（開發帳號）多數為自動核准**，送出後即可在 `마이페이지` → `개발계정` 看到。

### A3. 取得並正確設定金鑰 ⚠️ 最常見的失敗點

在 `마이페이지` → `개발계정` → 該 API 詳情頁，會看到**兩種**金鑰：

| 欄位 | 說明 | 本專案要用哪個 |
| --- | --- | --- |
| `일반 인증키 (Encoding)` | 已 URL-encode，含 `%2B`、`%2F` 等 | ❌ 不要用 |
| `일반 인증키 (Decoding)` | 原始值，含 `+`、`/`、`=` | ✅ **用這個** |

原因：`scripts/probe-korea-providers.ts` 用 `URLSearchParams` 組 query，它會自行 encode。
若你貼的是 Encoding 版，會變成雙重編碼，入口一律回 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` —
看起來像金鑰沒註冊，其實只是編碼錯。probe 腳本會在偵測到 `%XX` 時先警告。

新核發的金鑰**不會立即生效**，官方說明約需 1 小時（實務上偶有更久）。這段期間所有呼叫都會失敗，屬正常。

### A4. 額度與正式帳號

- `개발계정`：**每日 10,000 次**。本專案韓國目前 9 條路線 × 7 天 = 63 次／天，餘裕很大。
- `운영계정`：需另外提交 `활용사례 등록`（實際使用案例）後審核。額度較高。
- 若之後把韓國路線數擴大到數十條，再評估是否需要升級。

## B. 서울 열린데이터광장（首爾地鐵）

官方入口：<https://data.seoul.go.kr/>

### B1. 註冊與取得金鑰 — ❌ 外國人無法完成

> **本節保留僅供參考。** 先前版本誤述為「不需要韓國實名認證，一般 Email 即可」，
> 經實測為錯誤：註冊第 2 步強制本人認證，四種方式皆需韓國身分（見上方〈前提〉）。
> 若你**有**韓國門號或銀行帳戶才適用以下步驟；否則請改走 data.go.kr 的 15056777 鏡像。

1. `회원가입` 註冊 → **第 2 步「본인인증」需韓國身分，外國人在此卡關**。
2. 通過後進入 `나의 정보` → `인증키 신청`（申請認證金鑰）。
3. 填寫用途與服務網址後送出。
4. **金鑰即時核發**，可在 `인증키 관리` 看到。

### B2. 端點格式

首爾的 API 是路徑式，不是 query string：

```text
http://openapi.seoul.go.kr:8088/{인증키}/{TYPE}/{SERVICE}/{START}/{END}/{필터…}/
```

- `{TYPE}`：`json` 或 `xml`
- `{START}`／`{END}`：分頁起訖列（1-based，單次上限通常 1,000）

本專案關心的兩個服務：

| SERVICE | 用途 | 主要參數 |
| --- | --- | --- |
| `SearchInfoBySubwayNameService` | 依站名查站碼 | 站名 |
| `SearchSTNTimeTableByFRCodeService` | **站別時刻表** | 역코드 / 요일구분(1=平日 2=週六 3=假日) / 상하행(1=上行 2=下行) |

同一份資料在 data.go.kr 也有鏡像：`서울교통공사_역외부코드로 지하철 열차 시간표 검색`（編號 **15056777**）。
兩邊擇一即可；首爾站台不需要實名認證，建議走首爾。

**這個服務會回傳時刻表而非只有即時到站** —— 依官方資料集說明，欄位包含
호선、외부코드、지하철역코드、역명、상하행、**도착시간**、**출발시간**、출발역、종착역，
涵蓋 서울교통공사 1–9 號線。這正是本專案「查指定日期班次」需要的形狀。

> ✅ **站碼不需要另外建表。** `src/data/seoulSubwayStations.json` 已經內含全部 326 筆的
> `STATION_CD` 與 `FR_CODE`（例：시청 `0151`／`132`、충정로 `0243`／`243`、청량리 `0158`／`124`）。
> probe 腳本直接讀這份檔案去打時刻表，兩種站碼都試，回報哪一種可用。

### B3. 兩個要注意的技術限制

1. **端點是 `http://`，且走非標準埠 8088。** 伺服器端呼叫沒有 mixed content 問題，
   但若部署環境（Vercel serverless / GitHub Actions）有出口白名單或只允許 443，需要一併開放。
   本開發沙箱就因為未在白名單而回 `Host not in allowlist`。
2. 一般認證金鑰預設**每日 1,000 次**，可申請增量。首爾地鐵 305 站若逐站抓時刻表，
   一輪就會超過額度 —— adapter 必須只抓實際被查詢的路線，或分批快取。

## C. 設定到專案

### C1. 本機

寫入 `.env`（不要提交）：

```dotenv
# 城際列車（data.go.kr）— 使用 Decoding 版金鑰
KOREA_TAGO_SERVICE_KEY=""

# 首爾地鐵（data.seoul.go.kr）
SEOUL_OPENAPI_KEY=""
```

### C2. 執行探測

```bash
npx tsx scripts/probe-korea-providers.ts
```

腳本只讀不寫，不會動到 `src/data/scraped/`。它會依序回答：

1. 金鑰是否通過認證（先打最便宜的 `getCtyCodeList`）
2. **청량리／수원／동대구 是否在車站清單中**（決定 TAGO 值不值得接）
3. `서울 → 부산` 是否真的回傳班次列，以及**欄位名稱**
4. 用本地既有站碼打 **시청／충정로／청량리** 的站別時刻表，回報 `FR_CODE` 與 `STATION_CD` 哪一種可用、以及欄位名稱

把輸出的欄位名稱補回本文件的 §D 對照表，再開始寫 adapter。

### C2b. 檢查下載回來的檔案（免金鑰路線）

在瀏覽器下載 `15098251` 的 CSV 後：

```bash
npx tsx scripts/inspect-korea-filedata.ts ~/Downloads/서울도시철도_열차운행시각표.csv
```

腳本會回報：

- **編碼**（韓國政府 CSV 常見 EUC-KR／CP949，用 UTF-8 硬讀會變亂碼，
  進而讓所有站名比對靜默失敗 —— 腳本會自動偵測並選對解碼器）
- 欄位清單，以及自動判定哪些欄位是站名／到站／發車／方向／要日區分
- **시청／충정로／청량리／을지로입구／서울역 是否真的出現在資料裡**
- 若缺少站名或發車欄位，會直接警告「這不是時刻表」（例如誤抓成統計檔）

### C3. 排程

確認可行後，在 GitHub repo → `Settings` → `Secrets and variables` → `Actions` 新增
`KOREA_TAGO_SERVICE_KEY` 與 `SEOUL_OPENAPI_KEY`，並在 `.github/workflows/scrape.yml`
的 `Run scrapers` 步驟加入對應 `env:`（比照現有的 `SWISS_OJP_TOKEN` 寫法）。

- 首爾時刻表要用 `FR_CODE` 還是 `STATION_CD`（probe 兩種都試）
- 各服務是否需要單獨開通
- 파일데이터（CSV）下載是否免登入

probe 腳本的設計就是為了把上述每一項一次問完 —— 它的輸出應視為比本文件更權威。

## F. 接上之後會變成什麼

接上後韓國會從 `SnapshotScraper` 改為 `ProviderBackedScraper`，與香港／英國／美國同一條路徑：
先打官方 API，失敗才回退既有策展快照。`src/data/countries.ts` 的 `korea.scrape` 由 `snapshot`
改為 `provider_backed`，`search` 由 `scraped` 改為 `provider_then_scraped`。

覆蓋率會由 `stationCoverage.ts` 自動反映到車站選單與搜尋結果 —— 有資料的站會自動不再顯示
「無時刻表」標記，不需要另外維護名單。

**在那之前，不要用手工新增策展快照來讓更多站「有資料」** —— 那是發明時刻表，
違反 CLAUDE.md 明載的不合成原則，也會讓 `isIndicativeTimetable()` 之外的頁面誤把虛構班次
當成真實時刻對外發佈。
